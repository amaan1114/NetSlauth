# Prompt 1 — NetSleuth Project Foundation

We are building NetSleuth, an open-source, self-hostable security observability platform inspired by Prometheus and Grafana, but focused on network security monitoring and suspicious activity detection.

The platform should allow developers to deploy a lightweight monitoring agent inside their infrastructure and send security-relevant events to a centralized control plane.

## Technology stack

- Frontend: Next.js with TypeScript
- Backend: Node.js, Express and TypeScript
- Database: PostgreSQL
- ORM: Drizzle ORM
- Validation: Zod
- Real-time communication: Socket.IO
- Monitoring agent: Node.js with TypeScript
- Packet capture: tcpdump
- Deployment: Docker and Docker Compose
- Package manager: pnpm

## Architecture

Create a monorepo with the following applications:

apps/web
- Next.js dashboard
- TypeScript
- Tailwind CSS
- shadcn/ui

apps/api
- Express backend
- Modular monolith architecture
- REST APIs
- Socket.IO server
- Authentication
- Event ingestion
- Detection engine

apps/agent
- Independent Node.js monitoring agent
- Network event collection
- PostgreSQL log collection
- Communication with central backend

packages/database
- Drizzle ORM
- PostgreSQL schema
- Migrations
- Database connection management

packages/shared
- Shared TypeScript types
- Zod validation schemas
- Common event contracts

infrastructure
- Dockerfiles
- Docker Compose
- Environment configuration

## Important architectural rules

1. Keep the monitoring agent independent from the API.
2. Never couple detection logic directly to Express controllers.
3. Use dependency injection where it makes sense.
4. Keep business logic inside service and domain layers.
5. Use Zod to validate incoming data.
6. Use TypeScript strict mode.
7. Use environment variables for configuration.
8. Never hardcode credentials or secrets.
9. Make the project portable outside Replit.
10. Do not implement fake packet capture or claim simulated events are real observations.
